# Plantilla de Evidencia de Prueba de Aceptación - Caso 1020

## Información General

* **ID del Caso:** 1020
* **Título:** HU: Validación para marcar torneo como Finalizado
* **Historia de Usuario:** Como administrador de torneos, quiero que el sistema impida marcar un torneo como Finalizado si existen partidos pendientes de jugar o sin ganador definido, para garantizar la integridad deportiva de la competencia.
* **Área Funcional:** Torneos y Fixture / Integridad de Cierre de Competencias
* **Responsable:** Anderson Pineda
* **Dependencia:** Torneo creado con llaves/partidos pendientes (sin resultado)
* **Tipo de Ejecución:** API REST Client / Web Admin
* **Estado:** Planificado
* **Fecha de Ejecución:** 

---

## Guion de Pasos de Ejecución

1. Iniciar la Web API localmente en `http://localhost:5000`.
2. Obtener un token JWT de administrador e ingresarlo en la variable `@token` del archivo `docs/aceptacion/anderson/api/1020_finalizar_torneo_pendientes.http`.
3. Disponer del `torneoId` de un torneo activo que posea partidos programados en los cuales al menos uno carezca de marcador o ganador (`GanadorId = null`).
4. Ejecutar la solicitud HTTP PUT `/api/Torneos/{{torneoId}}` enviando `estadoId = 3` (Estado Finalizado).
5. Comprobar que el sistema rechace el cambio de estado respondiendo con código HTTP `400 Bad Request`.
6. Confirmar que el mensaje devuelto especifique la cantidad de partidos pendientes y la prohibición de finalización prematura.
7. Verificar que en la base de datos el torneo permanezca en su estado anterior (no pase a 3).
8. Registrar el resultado en la plantilla.

---

## Resultados

### Resultado Esperado
* La API responde con código `400 Bad Request`.
* Cuerpo JSON: `{"message": "No se puede marcar el torneo como Finalizado. Aún hay N partido(s) pendiente(s) de jugar o sin ganador definido. Todos los partidos deben completarse o cancelarse el torneo con una justa razón."}`.
* El estado del torneo se mantiene intacto.
