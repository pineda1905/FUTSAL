# Plantilla de Evidencia de Prueba de Aceptación - Caso 1006

## Información General

* **ID del Caso:** 1006
* **Título:** HU: Prevención de solapamiento de horarios en la misma cancha
* **Historia de Usuario:** Como administrador de la sucursal, quiero que el sistema bloquee reservas que coincidan en horario sobre la misma cancha, para evitar conflictos y doble reservación.
* **Área Funcional:** Reservas / Detección Preventiva de Solapamientos

* **Dependencia:** Caso 1003 (reserva activa previa existente en la cancha)
* **Tipo de Ejecución:** API REST Client / Web Admin
* **Estado:** Planificado

## Guion de Pasos de Ejecución

1. Iniciar la Web API localmente en `http://localhost:5000`.
2. Abrir el archivo `docs/aceptacion/anderson/api/1006_solapamiento_horario.http`.
3. **Paso 1 (Creación de Reserva Base):** Ejecutar la primera petición para registrar una reserva activa en Cancha 1 en el bloque de 18:00 a 19:00 horas. Confirmar respuesta `201 Created`.
4. **Paso 2 (Intento de Solapamiento):** Ejecutar la segunda petición intentando reservar en la misma Cancha 1 en el bloque de 18:30 a 19:30 horas (solapamiento parcial de 30 minutos).
5. Comprobar que la segunda petición sea rechazada con código `400 Bad Request` y mensaje: `"La cancha seleccionada ya cuenta con una reserva activa en el rango horario solicitado."`.
6. **Paso 3 (Exclusión de Canceladas):** Probar que si la reserva original es cancelada, una nueva solicitud en ese mismo rango horario sí es procesada con éxito (`201 Created`).
7. Copiar las respuestas JSON en la sección de evidencia.

---

## Resultados

### Resultado Esperado
* En colisión con reserva activa: HTTP `400 Bad Request` con mensaje `"La cancha seleccionada ya cuenta con una reserva activa en el rango horario solicitado."`.
* En coincidencia con reserva cancelada: HTTP `201 Created` (permite reutilizar el horario liberado).
